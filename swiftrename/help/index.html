SwiftRename Manual

Overview

SwiftRename is a tool for renaming and organizing multiple files at once. You can rename files by date, number them sequentially, add a prefix, and automatically sort them into a folder structure.

Select Folders

1. Click the folder icon next to the input folder to choose the folder containing the files you want to rename. Alternatively, you can drag and drop folders from Finder into the folder fields. Using the small arrow on the folder icon, you can quickly re-select a recently used folder.
2. Enable “Include Subfolders” to also process files within subfolders.
3. Choose an output folder where the renamed files will be copied or moved. The input and output folders can be the same (renaming in place).
4. Use “Swap” to switch the input and output folders. Use “Refresh” to reload both file lists.

Rename Modes

• Date only: Names files according to their creation date (e.g., “2024-01-15 at 14-30-00.jpg”)
• Date + original name: Adds the date before the original file name (e.g., “2024-01-15 at 14-30-00 - IMG_4523.jpg”)
• Numbering with prefix: Numbers files consecutively with a selectable prefix (e.g., “Vacation_0001.jpg”)
• Keep original name: Sorts files into the folder structure without changing the file name

If file names are identical, a counter is automatically appended (e.g., “_1,” “_2”).

Folder Structure

Files can be automatically sorted into subfolders by date:
• None: All files go directly into the output folder
• Preserve: Mirrors the input folder's subfolder structure
• Year: e.g., “2024/”
• Year/Month: e.g., “2024/01/”
• Year/Month/Day: e.g., “2024/01/15/”

If the files span multiple decades, additional decade folders will be created (e.g., “2011-2020/2015/…”).

For “Year/Month” and “Year/Month/Day,” the option “Full date in subfolder names” appears directly below the folder structure selector. When enabled, month and day folders contain the full date (e.g. “2024/2024-01/2024-01-15/” instead of “2024/01/15/”).

Name Preview

At the top of the input list you can choose between three views: list, tree and name preview (eye icon). In the preview, the planned new name and its target folder appear below each current file name – relative to the output folder, that is including the date and decade folders.

The preview requires a selected output folder and is recalculated as soon as you change the mode, prefix, folder structure or the “Use camera date” setting. With many files it fills in gradually, because the capture date has to be read for every file.

These are planned names: whether a file is skipped as a duplicate, and whether a counter (“_1”) has to be appended when target names collide, is only decided when the operation runs.

Camera Date (EXIF)

If “Use Camera Date” is enabled, the capture date from the EXIF data will be read for photos and videos. This is more accurate than the file creation date, which can change when copying.

Many photo formats are supported, including JPEG, HEIC, PNG, TIFF, and common RAW formats (CR2, CR3, NEF, ARW, DNG, RAF, and more).

If no EXIF date is available, the file creation date will be used automatically.

File extension filter

Use the “File Extensions” dropdown to filter the displayed files by type:
• Available extensions are automatically detected from the input folder.
• Select one or more extensions by clicking (⌘-click to toggle, ⇧-click for a range).
• “All File Extensions” resets the filter and shows all files.
• The filter is retained when switching folders, as long as the extensions exist there.

Duplicate Detection

If “Check for Duplicates” is enabled, duplicates will be detected before copying or moving—both in the input and output folders (the entire target tree). Detection is based on file size and a byte comparison of the file content; for images and videos, metadata such as EXIF is skipped. The date only matters for the additional image-content comparison.

Detected duplicates are shown in an overview with preview thumbnails. You can then decide whether to continue (duplicates will be skipped) or cancel the operation.

With the additional option “Compare image content only (slow)”, only the decoded pixel data of images are compared. Metadata such as keywords, tags or EXIF entries are ignored. This also detects identical images that were recompressed when saving keywords. This variant is significantly slower and only active when duplicate checking is enabled. Only images with the same file format and similar file size are considered as candidates. The maximum allowed size difference can be adjusted in Settings (⌘,) under “Size tolerance for image comparison” (default: 128 KB). RAW formats often require larger values, as metadata such as keywords can occupy several dozen KB per entry.

If a program has re-wrapped or re-exported a video, it counts as a separate file – even when picture and sound are identical. Videos have no content comparison like images do.

Copy and Move

• Copy: The original files are retained, and copies are created in the output folder.
• Move: The files are moved to the output folder.

Before executing, SwiftRename checks whether there is enough storage space on the destination drive. If there is insufficient space, a warning appears. You can continue the process anyway.

The total size of the files is displayed below the input list, and the free storage space on the destination drive is displayed below the output list.

Undo and Redo

Every file operation can be undone:
• ⌘Z: Undo the last operation
• ⌘⇧Z: Redo an undone operation

When undoing a copy, the copied files are moved to the Trash. When undoing a move, the files are restored to their original location.

Progress and Cancel

During processing, a progress bar with a percentage display will be shown. You can stop the operation at any time by clicking “Cancel.” Files that have already been processed will remain and can be undone using ⌘Z.

Keyboard Shortcuts

• ⌘O: Select input folder
• ⌘⇧O: Select output folder
• ⌘Z: Undo
• ⌘⇧Z: Redo
• ⌘,: Settings
• ⌘/: Show help
• ⌘Q: Quit app

Tips

• Before performing major renaming operations, create a backup of your files.
• Use the preview in the left pane to check the renaming results before executing.
• Right-click on a file in the list to display it in Finder.
• In Settings (⌘,) you can adjust the “Size tolerance for image comparison”. If problems occur, use “Save Log…” there to save the messages from the last seven days as a text file.
