1. Getting Started

What is sCollect?

sCollect is a media library app for macOS that lets you organize music, audiobooks, podcasts, movies, TV shows, e-books, PDFs, and any kind of collection (coins, models, stamps, and more). Each item is cataloged with its metadata (title, artist, album, genre, etc.) and can be played or edited directly within the app.

No Internet – by Design

sCollect does not rip CDs and does not fetch track information or artwork from the internet. That is not an oversight but a decision: Apple Music already does both, and does them well. Rip a CD there and then import the resulting files into sCollect. To do so, choose AAC, Apple Lossless, or MP3 in Apple Music’s import settings – the track information Apple Music has added is then stored in the files and comes along when you import them. With WAV, Apple Music keeps it in its own library, and the files arrive without track information.

In return, your library stays private. sCollect never contacts an internet address on its own, sends no information about your collection to any service, and needs no account. What you collect, how you organize it, and what you note about it never leaves your Mac – unless you share it yourself.

Creating a New Library

Choose a folder: On first launch, you will be asked to choose a storage location. Select a folder where sCollect should store the library data. A Media subfolder will be created for your files; the library itself (entries, playlists, settings) is stored as a .scollect bundle in the same folder.
Review settings: The settings will open automatically on the «Library» tab. Here you can change the default media folder or set up separate folders for individual categories (e.g. a dedicated folder for movies on an external drive).
Import media: Import your first files via File > Import Files… (⌘O) or File > Import Folder… (⇧⌘O).

Opening an Existing Library

If you already have a sCollect library (e.g. on an external drive), choose File > Choose Another Library… and navigate to the library’s main folder (the folder that contains the .scollect bundle). Alternatively, double-click the .scollect bundle in the Finder; sCollect will then ask for the enclosing folder if needed, so that artwork and media files can also be read.

Tip: You can have multiple libraries and switch between them via File > Choose Another Library…. Recently used libraries appear in the submenu. When switching, any ongoing synchronization or file organization is completed cleanly first.
Note: If the new library folder you pick contains leftovers from a previous library (detected by the presence of a .slaves/ directory), sCollect shows a confirmation dialog with the number of formerly registered copies. On confirmation, reachable copies are detached automatically from the old master, and the .slaves/ registry is then removed. Unreachable copies keep their binding to the old master and may need to be repaired manually.

2. Managing Your Library

Categories and Media Types

sCollect organizes your media into four main categories, each of which can hold up to ten media types:

CategoryDefault Media Types
AudioMusic, Audiobook, Podcast (+ 7 customizable)
BookE-Book, PDF (+ 8 customizable)
MovieHome Video, Feature Film, TV Show (+ 7 customizable)
MiscellaneousCoin, Model, Stamp (+ 7 customizable)

The labels can be changed in the settings (tabs «Category Labels» and «Field Labels»).

The two terms precisely: A category is one of the four fixed umbrella terms – Audio, Book, Film, Miscellaneous. A media type (type for short) is what you actually collect: Music, Audiobook, Podcast, E-Book, Feature Film and so on. Music, Audiobook and Podcast therefore all sit in the same Audio category. Wherever a function asks you for a scope – such as «Organize Library» or «Check for Missing Files» – you pick types: that is the only way to treat music separately from audiobooks. The category above them is there for expanding and collapsing, and toggles all of its types at once.

Sidebar

The sidebar on the left shows all active media types and your playlists. Click an entry to display its contents. Media types without an assigned name are hidden.

Change media type by dragging: Drag items from the list onto a media type in the sidebar to change their type. sCollect asks first – a type change moves the files to their new target location, on the master and on every copy, and with date-sorted filing it can produce name collisions.

Careful: Dragging onto a media type changes the type of existing items. To import new files, drag them onto the media list on the right instead. Files that do not belong to the library stay untouched when dropped on a media type – sCollect says so too.

Media Folders

By default, sCollect stores all imported files in the Media folder inside your library. However, you can assign a separate folder for each media type – useful if you want movies on a large external drive while keeping music on the internal SSD.

You can find the media folder settings under sCollect > Settings… > Library.

Deleting and the App Trash

Select entries and choose Edit > To Trash (⌘⌫) or, in the context menu, «Remove from library and delete from disk». sCollect does not delete immediately but moves the files into a hidden App Trash within each media folder (the .Deleted folder) – this works on any volume, including network shares without a System Trash, and is fast because it moves on the same drive. Press ⌘Z to undo a deletion instantly, ⇧⌘Z to redo it.

Open the App Trash via File > Library > App Trash… (disabled when empty). There you can restore selected or all entries, remove them permanently (to the System Trash if the volume supports it, otherwise deleted directly), or move them to a folder of your choice. Under Settings > Trash you decide whether emptying uses the System Trash and whether expired entries are removed automatically at startup (retention from 1 day, with a prompt). Connected copies mirror the deletion locally into their own .Deleted folder – with no file transfer over the network.

Show Duplicate Items

File > Library > Show Duplicate Items (⇧⌘D) scans the entire current category and makes the media list show only the duplicates found – just like Apple Music. For an existing selection, the context menu «Find Duplicates» is available.

The scan shows a progress bar and can be cancelled at any time. On large collections the first run may take a while; sCollect remembers the values it computes in the library, so every later run is markedly faster. When a file changes, its values are discarded and recomputed automatically.

What is compared

The scan works in several stages and merges everything it recognises as belonging together:

  • Metadata: same title and artist with a similar duration. Differing disc or track numbers within the same album rule out a duplicate; for audiobooks, differing album titles do as well.
  • File content: same file size and same beginning of the file.
  • Deep scan for identical audio: recognises the same recording even when the tags differ completely. It reads considerably more from disk and can therefore be controlled in the settings under Duplicates – «automatic» turns it off on network volumes.
  • Orphaned entries: an entry whose file is missing is attached to an existing sibling with the same base title in the same folder. That is the typical leftover after renaming «Title» to «Title (2)».

So that the comparison does not rest on wrong information, sCollect reads the tags of the candidate files beforehand and corrects diverging library values. Without this, faulty disc numbers could make different discs of an audiobook look identical.

The duplicates view

In the list, every entry proposed as a duplicate is tinted – one entry per group stays. The proposals are also selected; you can change the selection freely. A narrow status column adds two hints: a chain when several entries point at the same file, and a warning triangle when an entry's file is missing. The two can overlap.

Sorting and searching work in the duplicates view as well. The search filter only hides; «Delete selection» then takes the visible entries only, and the rest stays deletable once you clear the filter.

Delete selection asks first and then moves the selected entries together with their files to the App Trash (undo with ⌘Z). If a selected entry points at a file that a remaining entry still needs, or if its file is missing, only the entry goes – the confirmation names these cases separately. If the selection covers a group completely, the button is disabled.

You can also select entries yourself and delete them. Which entry stays per group is decided continuously – if you delete some by hand in between, another one takes its place, and no group ever loses all of its entries. «Exit Duplicates View» returns to the normal list.

3. Importing Media

Importing Files

Choose File > Import Files… (⌘O) to select individual files. Supported formats:

  • Audio: MP3, M4A, AAC, FLAC, WAV, AIFF, AIF, ALAC, CAF
  • Video: MP4, M4V, MOV
  • Books: PDF, EPUB
  • Miscellaneous: JPG, JPEG, HEIC, PNG, TIFF, WEBP

To add a CD, rip it with Apple Music and then import the files; why sCollect does not do this itself is explained under No Internet – by Design (section 1).

Importing a Folder

Use File > Import Folder… (⇧⌘O) to import all supported files from a folder, including subfolders.

Dragging In Files and Folders

Whatever you drag from the Finder onto the sCollect window takes the same route as the two menu items: folders are searched including their subfolders, the import dialog shows you beforehand what is coming in, and duplicate detection runs as always.

The same holds when you drag onto a playlist: files from the Finder are imported first and then placed in the playlist.

Books in Package Format

The Books app stores purchased titles as a package – from the outside it looks like a file, but it is in fact a folder. sCollect does not take such a package in, and says so: «Books package not imported», with the name alongside. A book is accepted as a single .epub or .pdf file.

Import Modes

In the settings (Library, Import box), you can choose how imported files are handled:

  • Copy to Library: Files are copied to the media folder. The originals remain untouched.
  • Move to Library: Files are moved to the media folder.
  • Leave in Place: Files stay where they are. sCollect only remembers the file location. Useful for files on network drives.

If a file cannot be taken into the library while copying or moving, sCollect creates no entry for it. The file stays unchanged where it is, and a message names it together with the reason.

Duplicate Detection

During import, sCollect automatically checks for duplicates (same title + artist, or same filename). If duplicates are found, a dialog appears where you can decide:

  • Import all: Imports all files, including duplicates.
  • Skip duplicates: Only imports files that are not already in the library.
  • Import selected: You manually choose which duplicates to import.

Automatic Organization

Imported files are automatically organized in a fixed folder structure: three letter levels from the artist name, then Artist/Album/File (e.g. A/AB/ABB/ABBA/Gold/Track.mp3). The path depends only on the metadata and stays stable as the library grows – files that are already filed are not moved.

Date-sorted filing: For media types where the moment matters more than the artist – photos, home videos, collections – you can choose filing by date in the settings instead. The files then land in year and month folders, and the file name carries the moment. The capture date governs where the file carries one; otherwise the item's date.

Tidying up titles on import: When sCollect derives a title from the file name, the camera's name often sits in front and a date behind it – something like IMG_20240115 Urlaub. Four switches under Settings > Import (when sorting by date) tidy that up. They only take effect for media types with date-sorted filing: anyone who wants to keep IMG or 20250401 in the name sorts alphabetically anyway.

  • Remove camera prefix from derived titles – on by default. IMG_20240115 Urlaub becomes 20240115 Urlaub. Only what sticks to the date without a space and appears in the list of known camera names is removed: Sam 2024-01-15 Konzert stays untouched.
  • Remove date from derived titles – on by default. That becomes Urlaub.
  • Add ISO date and time to the title – on by default. That becomes 2024-01-15 00-00-00 Urlaub, the same notation as in the file name, so that the title sorts the same way. If the title already carries a date, none is added. This addition is also written to the file, so that library and file say the same thing.
  • Date from the file name takes precedence – off by default. If the file name contains a date, that one applies – even when the file itself names one. It is the only one of the four that overrules an existing value instead of filling a gap.

The first two only touch derived titles – a title stored in the file's tag stays untouched; it is somebody's statement, not a derivation. The third adds there as well. If nothing were left after removal, the file keeps its name in full.

Tip: Movies are automatically classified: videos shorter than 70 minutes are categorized as home videos, longer ones as feature films. You can change the type at any time in the metadata editor.
Note: During import, sCollect detects MP4 files with old, non-standards-compliant DivX/Xvid sample entries (xvid/DIVX/DX50/DIV3) and renames them to .divx. These files are automatically routed to an external player during playback (see section 6). Standards-compliant MPEG-4 Part 2 streams (mp4v) are left untouched — AVFoundation can play them.

4. Browsing Your Library

Column View

The media list displays your entries in a configurable table view. You can:

  • Show/hide columns: Right-click a column header to open the column chooser.
  • Reorder columns: Drag column headers via drag & drop to the desired position.
  • Resize columns: Drag the divider between two column headers.
  • Sort: Click a column header to sort by that column. Click again to reverse the order. Hold Shift to add another column as a secondary sort – active columns show an arrow and an order number (e.g. Album↓1, Artist↑2). Option-click an active column header to remove that column from the sort again. Right-clicking a column header offers Reset Sorting to sort by the main column only.

Column Browser

The column browser (toggleable via the toolbar) provides multi-level navigation similar to the column browser in Apple Music. You can filter by genre, artist, and album by selecting entries in the respective columns.

  • Multiple selection with ⌘-click or ⇧-click
  • Which columns the browser shows is configurable in the settings

If a column has more values than set under Settings > Library > View for Max. entries per folder, it groups them into nodes by initial letters (A, AB, 0-9 …). Clicking a node filters to all values below it and expands it; a second click collapses it again, and the filter stays. With ⌘-click you can combine nodes and individual values. With the arrow keys, a node filters after a short pause without expanding; ↩ expands or collapses it and filters immediately.

Search

The search field in the upper right searches all relevant fields (title, artist, album, composer, genre, comment, work, movement name, year). Results are filtered in real time as you type.

Thumbnails

When the «Preview» column is visible, each row shows a small thumbnail (artwork or video thumbnail). Click the image of an already selected row to display a larger preview in a popover.

Spotting linked items

The optional Linked column – its header shows a chain symbol – marks with a checkmark every item whose file lies outside the media folders. Those are the files taken in with Leave in Place: sCollect only remembers where they are. Without a checkmark the file sits in one of the library's media folders. Since the import mode can be changed before every import, a library often contains both. Clicking the column header sorts by it and gathers all linked items together. The checkmark is display only – it cannot be clicked, because switching would mean moving the file.

5. Editing Metadata

Back Up Before Large Changes

sCollect writes into your files, not into a copy of them. So make a backup before large changes – for example before you change many entries at once in the Batch Editor or with Field Operations. Time Machine is enough.

Single-Item Editor

Double-click an entry (or select it and press ⌘I) to open the metadata editor. The editor has several tabs:

  • Info: Title, Artist, Album Artist, Album, Genre, Keywords, Year, Track Number, Disc Number, Composer, Comment, Grouping, Work, Movement Name, Movement Number, BPM, Rating, Favorite. For books (e-book, PDF), the Page Count field appears here instead of duration and BPM, and you can edit it directly.
  • Artwork: View, change, or remove the artwork. For movies: generate a thumbnail from any point in the video. A new image comes in via Load Image or Paste – or you drag an image file or an image from another application onto the artwork.
  • Sorting: Separate sort fields for Title, Artist, Album Artist, Album, and Composer. These fields are used for sorting without changing the displayed values (e.g. «Beatles, The» as the sort artist).
  • File Info: Technical details (file format, sample rate, bit rate, file size, file permissions, tag format) – plus four timestamps you can change. See «Timestamps in the File tab» below.
  • Attachments: Only for the Miscellaneous category. Documents, images or videos belonging to an item – see «Attachments» below.

With the arrow buttons ‹ and › at the top right of the editor, or with ⌃⌘← / ⌃⌘→, you page to the previous or next entry in the list without closing the editor (⌃ is the ctrl key). Your changes are saved in the process; if they cannot be saved, the editor stays on the current entry.

Year and exact date: Next to the year field, the calendar button (or a double-click in the year field) opens the entry of a full date. A checkmark on the button shows that a day-exact date is stored. sCollect keeps the date exactly as precise as it is in the file – if the file holds only a year, it stays a year; a day-exact date survives editing.

Timestamps in the File tab

The File tab shows four points in time, and all four can be set. They mean different things – that is why they sit side by side:

  • Capture date (file): The moment carried by the file itself – from the camera for photos, from the container for movies. Next to it is the source, that is, where in the file the value was found. Only for image and movie files; audio formats have no carrier with a time of day.
  • Creation date: The moment recorded by the file system. A different statement from the capture date: when copying, macOS sets it to now.
  • Import date (library): When the item entered the library. Purely a library value – no file carries it.
  • Modification date (library): The «Modified» column. It mirrors the file's modification time – so if you change it here, the file is set and the library follows. The field says so too: «sets the file date».

For movies, a note about the time zone sometimes appears next to the source. The moment in the container carries no zone information: the standard reads it as UTC, but not every camera writes it that way. On import, sCollect therefore compares the time in the container with the file's creation date – both come from the same camera clock, and their distance yields the reading. «no time zone» means: the case is open, the date is right, the time of day may be off by the zone offset. «local time» means: the camera has been recognised, and the moment meant stands right beside it. The file is not changed in the process – the reading is a piece of information, not an intervention.

All four are written only when you save, like any other field.

Copy-Protected Media

A purchased audiobook, a rented movie, a book with DRM: nobody may write into such files – a tag write would at best leave them unusable. sCollect detects the protection when opening the item and does not touch the file. Detected are, for books, the encryption of a PDF, Adobe DRM, Apple FairPlay, Readium LCP and EPUBs whose chapters are not readable text; for music and movies, Apple FairPlay and the widespread container encryption (Common Encryption).

You can still edit such an item. What you enter goes into a sidecar file with the extension .xmp that sits next to the file. In the editor you see this in two places on the File Info tab: in the note – «Copy-protected file: the details are stored in a sidecar file (.xmp) next to it; the file itself stays unchanged.», for a book «Protected book: the details are stored in a sidecar file (.xmp) next to it; the book itself stays unchanged.» – and in the tag format, which then reads Sidecar (XMP) together with the kind of protection.

The sidecar file belongs to the item and stays with it: if you rename the title, it travels along; it lies on every copy of the library just the same. Because nothing is stored in the file itself, the comparison with the file reports no deviation here either.

Two things are missing for protected media, and both for the same reason – they require the content to be readable: the capture date from the file and the thumbnail from a movie frame. On playing them see Playback (section 6).

Attachments

Items in the Miscellaneous category can carry attachments – a manual as a PDF, photos of a collector's item, a video. The Attachments tab in the editor takes them: via the Add attachment… button, or by dragging files onto the list.

Next to it are two options, and the choice applies to whatever comes next:

  • Link (default): The file stays where it is. The library remembers its location and finds it again even after a rename. It is not mirrored to copies – there is nothing to mirror – and when you remove the attachment it is not deleted: only the entry disappears.
  • Copy: The file is placed in the attachments folder next to the item and travels with it – onto every copy of the library as well.

In the list the icon tells you where you stand: a sheet for a copy, a chain for a link, a red exclamation mark when a linked file can no longer be found – deleted, renamed, or the drive is not connected. Then Locate… appears next to it, with which you find the file at its new location.

An image attachment opens via the arrow button in its own freely resizable window in front of the editor; other files open in their associated application. Likewise, clicking the main image on the left of the editor shows the picture at full resolution in this window – for an item whose file is not an image, the artwork.

The main image of an item in the Miscellaneous category also accepts an image you drag onto it. With ⌘V you insert an image from the clipboard as soon as the image is visible in the editor – even while a text field is active. If the clipboard holds text, ⌘V pastes it into the text field as usual. The image is only applied with Save.

Note: Attachments take effect only when you save – pending files sit in the list marked «will be copied on save» or «…linked».

Batch Editor

Select multiple entries and press ⌘I (or double-click the selection). The batch editor shows only fields that can be changed for all selected entries at once. A checkbox next to each field controls whether it will be written – only checked fields are saved.

Field Operations

For advanced editing, select the entries and choose Edit > Find/Replace… (⌥⌘F) or use the context menu. This opens the Field Operations window with the following tools:

  • Find & Replace: Search and replace text in one or more fields.
  • Swap/Copy Fields: Swap the contents of two fields (e.g. Artist ↔ Album Artist) – or take the value of one field one-way into the other. The button names the direction (e.g. «Title → Comment») so it is visible which field gets overwritten. Associated sort fields are carried along automatically. Copying asks first, because it cannot be undone: the target loses its previous content, and where the source is empty the target is emptied too.
  • Append to Title: Add text to the beginning or end of the title.
  • Date to Title: Insert the file’s modification date into the title.
  • Split: Split a field’s content at a separator into two target fields (copy or cut the source field). Numeric fields (track/disc/movement number, year) are supported; entries without a parseable number are skipped.
  • Separate name & sorting: Resolves a comma sort form (e.g. «Lennon, John») in entries with an empty sort field: the original value moves into the sort field, and the name field (Title, Artist, Album Artist, Album or Composer) is flipped into natural order («John Lennon»). Ambiguous cases with multiple commas are unchecked initially.

Rating and Favorites

Each entry can receive a rating from 0 to 10, shown as five stars in half-step increments: the first click on a star sets it full, a second click sets it half, and a third click clears it. There is also an independent favorite flag (heart icon) that can be toggled by clicking in the «Favorite» column.

Tip: An entry’s media type can be changed in the editor – but only within the same category (e.g. from «Music» to «Podcast», but not from «Music» to «Movie»).
Books: For e-books and PDFs, the «Duration» column shows the page count. If it is missing or outdated, you can re-read it from the files by right-clicking one or more entries > «Update Page Count».
Repairing Media File: The message «Repairing media file…» may briefly appear while saving metadata. It means the file was structurally damaged – typically an aborted recording or an incomplete download – and sCollect automatically fixed it before writing the changes. This happens rarely and only when needed. If the file was incomplete (truncated at the end), its length value is corrected; the missing media data at the end cannot be recovered (it was already missing from the file), but the metadata is preserved. If only an internal data block was misplaced, the repair is lossless. Files that cannot be safely repaired are left unchanged – sCollect then stops with a message instead of forcing a risky change.

6. Playback

Playing Audio

Select an audio entry and press Space or the play button in the player bar at the bottom of the window. The player bar shows:

  • Artwork, title, and artist
  • Timeline for scrubbing forward and backward
  • Volume control
  • Shuffle and repeat modes

Playing Video

Movies open in a separate video window. The controls appear automatically when you move the mouse. You can switch audio tracks and subtitles in the «Playback» menu if the file contains multiple tracks.

External Playback

Some formats are not natively supported by macOS / AVFoundation. sCollect detects this and opens these files automatically in an external player:

  • Special video formats: MKV, AVI, FLV, MPG, MPEG, VOB, DivX
  • Modern codecs: AV1 in MP4 (on older Macs without a hardware decoder)
  • High-resolution audio: DSD (DFF, DSF)
  • Other audio formats: OGG Vorbis, WMA

When a track is unreachable: Some files look playable and are only half so – an MP4 whose audio track macOS does not even offer, for instance. The result would be a silent movie. That is why sCollect checks on import which tracks the container carries and which of them actually arrive, and remembers the result on the item. When playing, such a file is handed to the external player without checking again.

One common case of this kind sCollect corrects right at import: MP3 audio in an MP4 container missing a descriptor field macOS expects. The change touches 19 bytes in the container – picture, sound, length, chapters and all tags stay untouched – and afterwards the file plays everywhere, not only in sCollect. A line in the log names every such case.

Copy-protected files sCollect always hands outside without checking them first: to the application macOS provides for them – for purchased titles, for example, to TV or Music. Only there is the key with which they can be played at all.

The preferred player is detected automatically: VLC, IINA or MPV (in that order). You can override the choice in Settings > Playback/Playlist > External player for unsupported codecs. If none of these players are installed, sCollect falls back to the default app for the format – we recommend VLC Media Player (free, open source).

Note: On first launch, sCollect shows a welcome text with this information. Tick «Don’t show again» to suppress it in future.

Playback Controls

SpacePlay / Pause
⌥⌘→Next Track
⌥⌘←Previous Track
⌥⌘↑Volume Up
⌥⌘↓Volume Down
⌃⌘FFull Screen

These commands are also available in the Playback menu; you can find all keyboard shortcuts in Chapter 12.

Playback Modes

  • Shuffle: Plays the current list in random order.
  • Repeat (List): Repeats the entire list after the last track.
  • Repeat (Track): Repeats the current track endlessly.

Remember playback position

sCollect can remember the last playback position for each entry and resume there next time – just like an audiobook or Podcast. Whether a position is remembered is set globally per media type under Settings > Playback/Playlist > Remember playback position (on by default for audiobooks, podcasts, and movies; off for music).

When playback resumes at a remembered position, the «From the beginning» button appears briefly – one click starts the track from the beginning instead.

Fixed start and stop markers

In the metadata editor, on the File Info tab, section Playback, you can set fixed markers: the entry then plays only from Start to Stop – handy for skipping an intro or silence at the end. Enter times in MMM:SS format, with thousandths after the comma (e.g. 3:45,500). The «Apply» button sets the respective field to the current playback position.

Note: The playback position and start/stop also apply to external playback (VLC, IINA, MPV). If copies of this library are set up, the position and markers are synced with them automatically – you can pause on one device and resume on another.

Create trimmed copy

From the start/stop markers you have set, sCollect can create a trimmed copy as a new entry next to the original – the original stays unchanged. In the metadata editor you will find the «Create trimmed copy» button under File Info > Playback. Alternatively, right-click one or more entries and choose «Trim to start/stop…».

Supported formats are MP4/M4V/MOV (video) as well as MP3, M4A/M4B, AIFF, WAV, and CAF (audio). Trimming is lossless – without re-encoding and therefore without loss of quality.

For the PCM formats AIFF and WAV you can additionally specify a gentle fade-in and fade-out – in seconds (5, 2.5) or like start and stop (0:05). A value that sCollect does not understand is marked red, and trimming only happens once both fields are valid. For the compressed formats MP3, M4A, and M4B, a dialog with two options opens before trimming: «Lossless (keep original format)» trims without re-encoding but does not allow fading. «M4A (AAC)» re-encodes instead – with a selectable bit rate (128 to 320 kbps) and optional fade-in/out, at the cost of a slight loss of quality.

Apple Music Export

Playlists can be sent to Apple Music: right-click a playlist in the sidebar and choose «Send Playlist to Apple Music». Alternatively, you can find this option in the menu under File > Send Playlist to Apple Music…

7. Playlists

Standard Playlists

You create a new playlist with the + next to the «Playlists» heading in the sidebar, and a folder for playlists with the folder icon beside it. Entries go in by drag & drop from the media list or via the context menu «Add to Playlist»; «Remove from playlist only» takes them out again without deleting them from the library.

A playlist under a category (such as Audio) only accepts entries of that category. For a mixed list, use the playlists at the very bottom of the sidebar. When you delete a playlist or a folder, sCollect asks first; a folder takes its playlists with it, while the entries themselves remain in the library.

If you drag files from the Finder onto a playlist, they are imported first – with the import dialog and duplicate detection – and only then go into the list; see Importing Media (section 3).

Adding and removing can be undone with ⌘Z; a removed entry returns to its old position. The same applies to «Remove from Library»: ⌘Z brings the entry back, together with its artwork and its positions in all playlists.

A Track More Than Once in a Playlist

If a track is already in the playlist and you add it again, sCollect asks first – once for all dragged or selected tracks, with their names listed below. Add Anyway adds them once more, Skip (Esc) leaves out the ones already there; new tracks are added in either case.

Each row is an entry of its own: you can select just one of two identical occurrences and take it out with «Remove from playlist only»; the other one stays.

Sorting and the «No.» Column

Each playlist has its own sort order, independent of the library and of other playlists. The No. column shows the position in the playlist, i.e. the order in which tracks were added; a playlist is initially sorted by it.

Clicking a column heading sorts by that column, a second click reverses the direction; holding down Shift adds another column, holding down Option removes one. Clicking «No.» always returns to the order in which tracks were added – sorting only changes the display, never the saved order. Playback follows the displayed order.

If a playlist already has its own column selection, show «No.» by right-clicking the column headings and choosing Customize Columns….

Column Browser in Playlists

The column browser can be shown in a playlist too – with the toggle at the top right above the list or with View > Show/Hide Column Browser (⌘B). It only shows values from the tracks in that playlist. Each playlist remembers its selection in the browser; whether the browser is shown, however, applies to all lists together.

Smart Playlists

Smart playlists are automatically populated based on rules. Create one via File > New Smart Playlist… (⌥⌘N) or the gear button next to the «Playlists» heading – at the very bottom of the sidebar or under a category. A smart playlist under a category only evaluates that category’s entries. Rules can be combined:

  • Text fields: Title, Artist, Album, Genre, etc. (contains, starts with, ends with, is…)
  • Numeric fields: Year, Rating, Plays, Duration (is, is greater than, is less than…)
  • Date fields: Date Added, Last Played (is, is greater than, is less than)
  • Boolean fields: Favorite, Compilation (is true/false)

Under «Match» you choose whether All rules must apply (AND) or Any of them (OR).

Tip: When creating a new library, sCollect automatically generates four smart playlists: «Recently Added», «Recently Played», «Top Rated», and «Most Played».

8. External Drives

Library on an External Drive

You can create a sCollect library on an external drive or move an existing one there. Please note:

  • When you connect the drive to a different Mac, sCollect needs to be granted access once. A dialog will appear automatically, allowing you to select the media folder.
  • For the best file access, we recommend adding sCollect to Privacy & Security > Full Disk Access in System Settings.

Custom Folders per Media Type

Under Settings > Library, you can assign a separate folder for each media type. For example, movies can reside on a large external HDD while music stays on the fast internal SSD.

If such a folder is unreachable – the drive is disconnected, the network volume not mounted – sCollect locks that media type: nothing is written, nothing moved and nothing synchronised, and the entries stay unchanged. That is deliberate. A media type whose folder is missing would otherwise silently end up in the default folder, and afterwards the library would no longer know where the files belong.

A warning banner names the affected types, and in the settings the folder is shown with a note that it is currently unreachable. Reconnect the drive and the lock ends by itself.

Redirecting: If you choose a different folder for a media type while the previous one is unreachable, nothing can be moved – the files are out of reach. sCollect then offers to redirect the entries to the new folder: it searches there for every file, first by the previous path, then by file name, and shows you a preview with three numbers beforehand – found by path, found by file name, still without a file. Redirecting changes only the library, not a single file.

Finding Missing Files

If files have been moved or the drive was not connected, you can run a check via Settings > Library > Check for Missing Files. sCollect will show all unreachable entries; Search Folder… looks for them in a folder of your choice (see below).

If copies are registered for the master, the window also shows a Restore from copies button. sCollect searches all reachable copies for the missing files and copies the first match (size > 0) back to the master. Useful after an accidental deletion when the Trash has since been emptied – as long as at least one copy still has the file, it can be recovered.

Marking and Showing Missing Items

File > Library > Mark Missing Items checks the whole collection once and remembers the result on the entry. After that the list only reads this mark – it checks nothing while you scroll, because in a large library that would take too long. An entry without a file gets an orange warning triangle in front of the title.

A disconnected drive does not mean that the file is missing. What is not connected, sCollect cannot check either. The report counts such entries separately as not checkable, and their mark stays as it was – it is neither set nor removed. The report after the run therefore names checked, missing and not checkable entries, and in addition how many marks were newly set and how many were removed.

File > Library > Show Missing Items (⇧⌘F) is a toggle: the list then shows only the marked entries. A banner above the list says why it is so short and offers the way out in the same place with Exit Missing Items View. As long as no mark is set, the toggle is dimmed.

The view freezes on being switched on which entries it shows. If you relink one of them, its row stays where it is and gets a green check mark – that way you do not lose track of what you have already managed while working through the list. The counter in the banner shows both: how many are still without a file and how many are done. In the normal view the marking disappears.

If you have moved a file out of the media folder in the Finder, sCollect can often still find it through its bookmark – it is then not missing, but lies outside the library. The report names such entries on a separate line, and Bring Back moves the files back to their place. If sCollect is not allowed to remove anything at the other location, it copies instead.

Finding a Missing File Again

If the file is missing, the entry cannot be edited. That is deliberate: there is nothing to write to, and an editor that opens and only refuses when saving throws away your work. Instead the context menu offers Find File…. The dialog opens in the last folder that still exists and shows only files with a matching extension.

The file that is found is brought back into the library, not merely linked. A managed entry therefore stays managed, even if you find the file again somewhere else.

If, on the other hand, the drive is not connected, there is only a dimmed note in this place: Drive not connected. Offering a search here would be an invitation to attach the entry permanently to the wrong file.

In the context menu an entry without a file offers only the commands that actually work. Play, show in Finder, convert, delete from disk and everything else that needs the file is not offered at all.

If you select several entries and some of them have no file, the batch editor skips those and states their number above the fields; it opens with the rest. If all of them lack the file, it does not open.

Finding Missing Files in a Folder

Instead of looking for each file individually, you can give sCollect a folder in which the missing files are located. Three ways lead there: the context menu item Find Missing in Folder… for the selected entries, Search in Folder… in the report of Mark Missing Items for all marked ones, and Search Folder… in the Missing Files window.

  • Unambiguous matches are assigned by sCollect itself – by name and size, for renamed audio and video files by size and duration.
  • Ambiguous or uncertain matches – such as two files with the same name in different subfolders, or a renamed book – end up in a window for you to decide. Nothing is preselected there; only once you choose a file can the entry be applied.
  • If the match lies outside the library, it is copied to the right place; if it lies in the media folder of its own type, it is moved there.
  • A linked entry is relinked when the import mode is «Leave in Place»; with any other mode the file comes into the library, and the entry's values are written into it.
  • If a file that is found already belongs to another entry, it is skipped.

The final message states what was assigned automatically, applied by you, not found or skipped; the log lists the paths.

Libraries on Network Shares

sCollect can also operate libraries on SMB or NFS shares. Please note:

  • When opening: If the volume is offline, no automount attempt is made – sCollect shows a warning. You can still open the library, or connect the volume manually first.
  • When deleting: On network shares too, deleted files first go into the App Trash (the .Deleted folder in the respective media folder) and can be restored from there. They are removed permanently only when you empty the App Trash (see section 2). Since shares usually have no System Trash, they are then deleted directly.

9. Settings

Open the settings via sCollect > Settings… (⌘,). The settings are divided into several tabs:

General

  • Import mode: Copy, Move, or Leave in Place (default for future imports).
  • Multi-value separators: Characters used as separators for multiple artists/genres in a single field (default: &, /, ;).

Library

  • Default media folder: The main folder where imported files are stored.
  • Folders per media type: Optional custom folders for specific media types.
  • Library location: Shows the current storage location and allows switching.
  • Import: How imported files are handled (see «Import Modes»).
  • View > Max. entries per folder: From this many values on, the column browser forms nodes by initial letters. Affects only the display, not the folders on disk.

Category Labels

Here you can change the labels for categories (Audio, Book, Movie, Miscellaneous) and media types (Music, Audiobook, etc.). Media types without a name are hidden in the sidebar and thus deactivated.

Field Labels

Change the column labels (e.g. «Artist» to «Author» for e-books) globally or per media type.

For many media types sCollect already brings fitting names along: for an audiobook «Artist» is called Author by itself, for a feature film «Album» is called Studio. For the Miscellaneous category the names follow the collecting field:

  • Coin: Mint, Country, Series, Engraver, Catalog
  • Model: Manufacturer, Brand, Series, Engineer, Scale
  • Stamp: Postal Administration, Country, Issue, Designer, Catalog

The remaining slots under «Miscellaneous» carry the model names until you name them yourself. All of these defaults can be overridden here – they are a suggestion, not a fixture.

Playback/Playlist

  • Apple Music export: Settings for exporting playlists to Apple Music.
  • Video window always on top: The video window always stays above all other windows.
  • Volume during slow motion / frame step: Volume reduction in dB during slow-motion and single-frame mode.
  • External player for unsupported codecs: Preferred player for codecs that AVFoundation cannot decode (MKV, AVI, AV1 without HW decoder, DivX, etc.). Detected: VLC, IINA, and MPV; if none are installed, the default app is used.

Synchronization

Manages the connection to master and copy libraries. Connect another library as a copy, monitor pending sync operations, and project the master state onto a copy. See section 11 for details.

Language

The app’s language follows the system settings. To change it: System Settings → General → Language & Region, then scroll all the way down to the “Applications” section.

10. Convert Format

Convert Audio or Extract Audio from Video

Select one or more audio or video entries in the list, right-click, and choose Convert Format… or Extract Audio As… for movies. The dialog offers the following settings:

  • Output format: AAC, MP3, HE-AAC, ALAC (lossless), WAV, or AIFF. «Audio passthrough» is also available – the audio bitstream is copied 1:1 into an MP4 container without re-encoding.
  • Audio parameters: Channel layout (as original / stereo / mono), sample rate (original / 22050 / 44100 / 48000 Hz), and for PCM/ALAC the bit depth.
  • Compression: For MP3/AAC/HE-AAC: choose between fixed bitrate or variable bitrate (VBR) with quality slider.
  • Target: Two choices – Library (the converted file lands in the chosen audio category of the library; preset to «Podcast», or «Audiobook»/«Music» as fallback if Podcast is not active) or External (use the Choose… button to pick a folder outside the library – the original stays untouched, the converted file is not added to the library).
  • Original handling: For target «Library»: keep, move to Trash, or replace with conversion. For «External» always kept.

Metadata and artwork of the original are always copied over. When importing into the library, the file is moved into the audio category folder; no duplicate check is performed – what happens to the original is controlled by the «Original» combobox.

iPod Preset

The button iPod-compatible (AAC-LC, 256 kbps) sets the parameters to a combination maximally compatible with older iPods (Shuffle, Nano, Classic): AAC-LC in MP4 container, 44.1 kHz, stereo, 256 kbps CBR. Not passthrough, so HE-AAC source material is re-encoded to AAC-LC.

Tip: All convert settings are saved per library – the next time you open the dialog, your last configuration is already preselected.

11. Synchronization (Master/Copy)

Concept

sCollect can synchronize multiple libraries: one library acts as the master, one or more others as copies. Changes to the master (tag edits, imports, reorganize) are automatically mirrored to the connected copies – with separate media folders and paths per copy. For example, the full library can live on a large external drive as the master, while a notebook holds a reduced or identical copy.

Synchronization Is Not a Backup

A copy protects against absence, not against loss. Every change is mirrored – deletion included: whatever goes into the trash on the master goes into the trash on every copy as well, and once it is removed for good it is gone everywhere. The same holds for a field you overwrite by mistake: the copies take the new value, not the old one. A backup therefore has to sit outside this chain – Time Machine, say, or a copy run onto a medium sCollect knows nothing about.

Add a Copy

Open Settings > Synchronization and click Add Copy…. Choose another sCollect library to serve as the copy. Note: the candidate must not already be a copy of another master and must not itself be a master with registered copies.

The best moment is when nothing is pending. A new copy first has to receive everything it lacks – if that coincides with a transfer already under way, both take longer, and in the worst case every copy ends up waiting for the others. A glance at the sync symbol in the sidebar is enough: if it shows no number, this is the right moment.

Initial File Mirroring

On Push, sCollect writes the copy’s library database (items, playlists, settings), but does not automatically copy all media files during initial setup. For the initial bulk mirroring of files, an external tool such as FreeFileSync is recommended. Afterwards, sCollect handles all ongoing file operations (import, move, delete, tag write, artwork) itself.

Project (Push)

With Project in the slave row, the master rewrites the slave’s library.json from scratch – all items, playlists, and content-relevant settings are taken from the master. The slave’s pending sync queue is also reset.

Live Broadcast

During normal operation, every change to the master is automatically propagated to all connected copies. For unreachable copies, changes are stored in a queue and applied as soon as the copy becomes reachable again. The number of pending operations per copy is shown in the sync settings («X pending» badge).

A deletion on the master is mirrored so that each copy moves its own file locally into its .Deleted trash – with no transfer over the network. Restoring on the master brings the copies' files back locally too; only when entries are removed permanently on the master do the copies discard their trashed file.

Pending Operations

If a copy is offline or a synchronization has failed, pending operations accumulate. Per copy, two options are available:

  • Run Pending: Attempts to apply the backlog. If a transfer fails, it stays where it is and the run stops – nothing is lost, it is simply tried again next time.
  • Discard…: This copy skips its entire backlog. That is a forfeit, not a release: it counts as up to date afterwards without the changes ever having reached it – for this copy they are gone. That is why Project or Resolve Sync Errors… always belongs afterwards; only that establishes what it actually lacks and fetches it.

When One Copy Falls Behind

All copies work through the same list, and they do so in lockstep: only once a change has reached every copy does the next one follow. This is deliberate – it keeps a copy from quietly falling behind and carrying a state months later that nobody can place any more.

The consequence: if one copy is stuck, the others wait. The sidebar then shows «Waiting for another copy» next to them. That is not a fault but the brake, and it releases by itself as soon as the missing copy becomes reachable again – drive connected, network volume available.

If it stays that way, there are two routes: make the stuck copy reachable and use Run Pending – or choose Discard for it and then Project. The second route costs that one copy its backlog but releases the others immediately.

Resolve Sync Errors

With Resolve Sync Errors…, the tag data of each file in the copy is compared with the master and rewritten if different. Filters for rating, genre, and year allow stage-by-stage processing. Missing slave files are copied from the master. Useful after manual changes or after an initial mirroring with an external tool.

Read-Only Copies

A copy can be marked as read-only – then import, delete, and tag edits in the copy are blocked, so changes won’t be overwritten on the next sync.

Organize Library

Via Settings > Library > Organize Library (or the button above the media list), sCollect tidies the managed files. A dialog asks for the scope and the options first.

Scope

At the top you pick the media types to process – expandable under their category, with the number of objects per type. Everything is preselected. This matters because a grown library is rarely equally well kept everywhere: if you did a lot of find & replace on music but hardly any on audiobooks, you are better off treating them separately.

What the run does

  • Merge duplicate entries: If two entries point at the same file, that is not a duplicate but an error in the library – there is only one medium. The older entry stays and inherits whatever says more from the other: the higher rating, the favourite, the higher play count, a remembered playback position. Playlist slots of the abandoned entry then point at the remaining one.
  • Arrange: Entries whose file is not at its target path are moved there (Artist/Album, fixed folder levels). Sidecars, artwork and attachments come along.
  • Reconcile folder: The media folders are scanned for files that were copied in by hand and have no entry yet. New files are added. If an existing entry has lost its file and a find matches it, the entry is healed onto that file and takes over its metadata. If the original is still there, the file is added as a genuine duplicate with a « (2)» suffix in title and file name.
  • Remove orphaned entries: Entries whose file is demonstrably gone are deleted – the entry only, since the file no longer exists. «Demonstrably» means: the volume is mounted, not all files on it are missing at once, and for managed objects the media folder is reachable. If any of these does not hold, the entry is left alone – a disconnected drive must not cost you entries.

Reconcile metadata with the files

This option is off by default and answers the question of what counts when library and file disagree:

  • File wins: the file's tag counts, the library is corrected. No file is written.
  • Library wins: the stored value counts and is written into the file. This cannot be undone.

Below that you pick the fields involved – everything is ticked, unticking is deliberate. The run writes nothing at first: it only collects the differences and then shows them in a preview, grouped by field. There you can untick a whole field at once, or expand it and untick individual rows; a pencil icon marks files that were changed from outside since the last access. Only «Apply» writes.

BPM and lyrics are not offered: they are not stored in the library at all, so there is no value to compare against. They live in the file only and are preserved when writing. The artwork is included, but compared by its size – two different images that happen to have the same byte count are not recognised as different.

Synchronize changes with the copies

On by default. If you turn it off, the connected copies are left untouched and drift apart as a result – sensible only if you run a full comparison with an external tool afterwards. Projecting does not make up for it: it only maps paths and reports what is missing at the destination; it moves nothing on the copy.

During the run, modifying actions are locked; a progress bar with a Cancel button is shown and the Mac is kept awake so external volumes do not disconnect. At the end a window summarizes what was moved, merged, newly added, healed, added as a duplicate and removed.

Tip: If you regularly update a copy with an external tool (e.g. FreeFileSync), you can simply run Project on the copy after each mirroring – the pending queue is reset automatically.
